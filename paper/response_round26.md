# Response to an outside review (Gemini)

An outside reviewer read the 39-page PDF of the manuscript. Two checkers then verified each of the reviewer's claims against the code and data, and the author chose which changes to apply. Edits were made to `paper/paper.md` only. The Abstract did not change. Each new number was recomputed from the data files, and each new sentence was checked against the Lean source or the data before it was written.

## Design question

The reviewer asked what the model adds over the fallback, and whether the layer is meant for a longer output such as a discharge summary. The Introduction now states the intended use: the medication section of a longer model output, where the layer releases or blocks only the medication instructions. It says this use was not evaluated, and that a deployment must keep doses, routes, frequencies, and drug names out of the surrounding text or pass that text through the layer. A new Results paragraph, "What the model adds in this evaluation," compares the model with the fallback. The fallback prints a line for 118 of 120 test cases, the same count as Qwen3.5-4B after rewrites in the slot and slot daily conditions. The slot prompt also shows the daily form, and 104 of Qwen3.5-4B's 118 released slot outputs state a daily total, so the paragraph reports both counts. The paragraph also says that whether either addition helps a patient was not measured. The existing statement that the fallback differs from model text was kept, because the fallback prints no framing sentence and no daily total.

A second paragraph, "What narrowing the specification showed," states that each later version removed freedom that the attacks had used, and that version 2.1 released text is close to a template. It reads the protection for numbers from an untrusted model as coming from that narrowing, labels that reading as the authors' interpretation, and names the input reader rules and the completeness default as other changes between versions. It does not repeat the version 1 counts, which the earlier paragraph in Results states. The manuscript has no Discussion section, so both new paragraphs sit in Results.

The reviewer's Option 2, a question-answering task, was declined. The layer cannot check that the model chose the right order for a question. A question-answering task would also need `--allow-omissions`, because an answer that names one order would otherwise be blocked for omitting the others. That test would measure the option, not the default layer.

The reviewer's proposal on constrained decoding is now in the paper. The sentence that said constrained decoding might raise release rates was replaced with the reviewer's argument. It says constrained decoding is a natural complement, that it would remove format failures (885 of Llama 3.2 3B's 913 blocked slot outputs were blocked as unbound), and that the layer's checks on the substituted text still need to run. The pairing is marked as untested. The reviewer also suggested a shorter version in Related work or Discussion. That was not added, because this round replaced one sentence only.

## Technical notes

It does not read drug names, and the paper does not say it does. A future-work sentence was added after the related-name paragraph in Limits. It says a future version could accept an optional ingredient code and block two active orders that share one, and that version 2.1 does not do this. The code-based check itself was not built. The reviewer's estimate was about one day of Lean work, three to five days for the reader and fixtures, and one to two weeks for ingredient mapping and clinical review. On the combined theorem (H), the reviewer's proposed `render_released_spec` was not added. Lean cannot prove that hypothesis, and the paper states it as the authors' judgment. The paper still says that no single theorem states the conjunction, and that stays true until such a theorem exists. The statement is deferred, with an estimate of two to four hours for a Lean author.
