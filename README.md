# DoseGate

DoseGate is a small program, written in Lean 4 and proved to meet a written specification, that sits between a language model and the patient. The model writes each medication instruction with slots such as `{{dose:m1}}` instead of values. DoseGate fills each slot from the FHIR MedicationRequest it receives or blocks the whole output. The proofs guarantee, for every model and every output, that every drug name, dose, daily total, route, and frequency the layer fills from a slot is the corresponding value of the single active order the slot names, and that each filled value appears only inside an instruction for its own order that states its dose, route, and frequency. With the default vocabulary, every other sentence uses only a small set of framing words; a deployment that adds words with `--extra-words` can release a drug name outside any instruction. The code that reads FHIR JSON into Lean values is tested, not proved.

This is version 2.3. The history of versions 1, 2, 2.1, 2.2, and 2.3, and the held-out adversarial rounds that led to them, is described in the paper.

## Layout

- `DoseGate/*.lean`: definitions (exact decimals, units, the FHIR subset, the slot parser, word classes, the renderer, the specification).
- `DoseGate/Proofs/*.lean`: the proofs. `lake build DoseGate.Proofs` checks all 238 theorems.
- `DoseGate/Json.lean`, `DoseGate/Lexicon.lean`, `Main.lean`: the FHIR input reader, the embedded drug-name lexicon, and the command-line tool. This code is tested, not proved, except that `DoseGate/Proofs/ReaderNumbers.lean` proves that the dose, unit, and timing of each order equal the fields of the parsed JSON. The JSON text parser, the route, and the drug name are not proved.
- `data/prose_words.txt`: the 1,926 words that `--number-only` allows in free sentences, embedded in the binary by `DoseGate/ProseWords.lean`. Lake does not track this file, so after editing it delete the `ProseWords` build outputs under `.lake/build` before rebuilding. `tests/check_prose_words.py` checks the list.
- `data/rxnorm_names.txt`: the drug-name lexicon, every RxNorm ingredient, precise ingredient, multiple ingredient, and brand name (27,369 names, RxNorm release of 2 November 2026); `data/README.md` records the source and `data/build_rxnorm_names.py` rebuilds it.
- `Baseline.lean`: the comparison filter used in the evaluation. It uses the same input reader and slot formatting but checks model text only for braces, digits, and unit words.
- `tests/`: regression tests (`bash tests/run.sh`; `tests/raw/h3_*` are the 35 round h3 requests that version 2.1 released as misstatements, and `tests/raw/h4_*` are 21 round h4 requests that version 2.2 released, the 10 misstatements, 6 requests whose requester or recorder reference names a doctor, nurse, or pharmacist in its id, and 5 requests that used the same identifier, fullUrl, or resource channels but were labeled faithful; all must now block or error), the differential fuzz test of the input reader (`python3 tests/fuzz_reader.py --core v2 --seed 7 --count 20000`, 80 mutation kinds), and `tests/Axioms.lean`, which prints the axioms of every theorem (`lake env lean tests/Axioms.lean`).
- `eval/`: the evaluation scripts and data (below).
- `paper/`: the manuscript.

## Build

Install Lean with elan (the toolchain, Lean 4.35.0, is pinned in `lean-toolchain`), then:

```bash
lake build DoseGate.Proofs
```

```bash
lake build dosegate dosegate-baseline
```

## Use

```bash
echo '{"medicationRequests": [...], "output": "Take {{drug:m1}} {{dose:m1}} {{route:m1}} {{frequency:m1}}, which is {{daily:m1}}."}' | .lake/build/bin/dosegate render
```

The reply is `{"status":"ok","text":...}`, `{"status":"blocked","reason":...,"detail":...}`, or `{"status":"error","message":...}`. `dosegate serve` reads one JSON request per line. The reader is version 2.3, and none of its rules can be turned off.

Identifiers. Every identifier the reader meets must be opaque: a UUID (8-4-4-4-12 hexadecimal digits), or a token of at most 32 letters, digits, hyphens, and periods that begins with at most three letters, carries no other letters, and includes a digit, where a prefix of two or three letters may not be a word from the layer's word lists (a number, unit, route, frequency, or qualifier word, a vocabulary or sentence-shape word, or a drug-name stop word) or one of the prescribing abbreviations in `idStopWords` (bd, od, tds, qds, tiw, biw, sos, npo, dc, ud, am, pm, and so on), so `prn1`, `qd-1`, `iv1`, `bd1`, and `npo1` are refused while `m1`, `pat1`, `med-42`, and `rx12.3` are accepted; a single letter is not a word, so `g1` and `t1` pass. The rule covers the ids of MedicationRequest, Patient, and Medication resources, the bundle id, every `meta.versionId`, the id in a `urn:uuid:` fullUrl, the id inside every reference string of the form `<Type>/<id>` or `urn:uuid:<id>` (`subject`, `encounter`, `requester`, `performer`, `recorder`, `medicationReference`, `priorPrescription`, `reportedReference`, `reasonReference`, `supportingInformation`, `basedOn`, `insurance`, and `eventHistory`; a reference of any other form, such as an absolute URL, still fails closed as in version 2.2), and the request's `patient` field; any other value refuses the whole request. Error messages quote the offending value (an id, a fullUrl, a reference), so, like block details, they must not be shown to a patient. An absolute (http or https) `fullUrl` must end with the type and id of its resource, as FHIR requires. Identifiers are therefore not a text channel: a deployment whose server issues ids with words in them must map them to opaque tokens before calling the layer.

Request errors. The whole request is refused with an error reply when: a request, bundle, or bundle entry has a key the reader does not accept (an unknown key with a null value is ignored; a bundle may carry `resourceType`, `id`, `meta` with `versionId` and `lastUpdated`, `type`, `timestamp`, `total`, `link` entries with a relation of self, next, previous, first, or last and an http or https url, and `entry`; an entry may carry `fullUrl`, `resource`, and `search` with a mode of match, include, or outcome and a numeric score); the `bundle` or `medicationRequests` key is null; a bundle entry is not an object, has no `resource`, or has a `resource` without a non-empty string `resourceType`; a bundle entry's resource is not a `Patient`, a `MedicationRequest`, or a `Medication` (a nested Bundle, a MedicationStatement, MedicationDispense, or MedicationAdministration, a Flag, Communication, Condition, CarePlan, Practitioner, or any other FHIR R4 resource type, and any name that is not an R4 resource type, each refuse the request with a message that names the type; `Patient` entries are accepted but not read: a Patient may carry only the Patient fields of FHIR R4 (`identifier`, `active`, `name`, `telecom`, `gender`, `birthDate`, `deceasedBoolean` or `deceasedDateTime`, `address`, `maritalStatus`, `multipleBirthBoolean` or `multipleBirthInteger`, `photo`, `contact`, `communication`, `generalPractitioner`, `managingOrganization`, `link`) with `resourceType`, `id`, and a `meta` limited to `versionId`, `lastUpdated`, a US Core or base Patient `profile`, and an empty `security`, and any `contained` resource, narrative `text`, extension anywhere in it, `implicitRules`, `language`, or unknown key refuses the request; `Medication` resources are read only through a `medicationReference`); an order has no `id`, or any resource id, bundle id, `meta.versionId`, fullUrl id, reference id, or `patient` field is outside the opaque identifier rule above (the FHIR `identifier` field of an order is different: as in version 2.2 it makes the order fail closed); an absolute `fullUrl` does not end with its resource's type and id; a `medicationReference` matches more than one `Medication` resource in the bundle (by relative reference, by entry `fullUrl`, by the resource id named in a `urn:uuid:` reference, or by an absolute `fullUrl` that ends in the reference), or a `Medication` resource is referenced by no MedicationRequest; an order's `status` or `intent` is missing or is not a FHIR R4 code (case variants such as `Active` included); an order has a `doNotPerform` or `reportedBoolean` that is neither a boolean nor null, or a wrong-typed `medicationCodeableConcept`, `dosageInstruction`, timing, route, dose, `asNeededBoolean`, `sequence`, `dispenseRequest`, or `meta` field, such as a `frequency` or `period` that is not a whole number; a MedicationRequest has no `subject.reference`, or one that is not `Patient/<id>` or `urn:uuid:<id>` (an absolute URL is refused); the MedicationRequests do not all carry the same subject reference; or, with a `patient` field, the common subject is not that patient. Valid statuses other than active (on-hold, cancelled, completed, entered-in-error, stopped, draft, unknown) and valid intents that are not order intents (proposal, plan, option) make the order inactive, and inactive orders are omitted without a block.

Orders that fail closed. An order keeps its name but has no usable dose, timing, or route, so under the default settings every output for that patient is blocked and `dosegate fallback` blocks too, when it carries anything the reader does not interpret: `reportedBoolean` true or any `reportedReference` key (even a null one); `priorPrescription`; an extension anywhere in the order; a key outside the 37-key allowlist (a null value still counts as present); `note`, dosage `text`, `additionalInstruction`, or `patientInstruction` (unless `--ignore-free-text` is given); `statusReason`, `identifier`, `groupIdentifier`, `instantiatesUri`, `instantiatesCanonical`, or `implicitRules`; a `reasonCode`, `category`, `performerType`, or `courseOfTherapyType` entry with a `text`, with a coding `display` (other than the standard display of a category or course-of-therapy code), with a coding `version`, or with a coding whose system is not one the reader knows (SNOMED CT or ICD-10-CM for reasons, the HL7 category and course-of-therapy code systems) or whose code does not have that system's shape; a `courseOfTherapyType` that is not `continuous`; a `priority` outside routine, urgent, asap, and stat; a `language` that is not a two- or three-letter tag with an optional two-letter region; an `authoredOn` that is not a FHIR dateTime; a `meta` with `tag`, `source`, or a non-empty `security`, a `profile` outside the US Core and base MedicationRequest profiles, or a malformed `versionId` or `lastUpdated`; a `dispenseRequest` with anything but `numberOfRepeatsAllowed` (a whole number) and `quantity` (a numeric value with a unit from the dose unit table), so `expectedSupplyDuration`, `validityPeriod`, `performer`, `initialFill`, and `dispenseInterval` all fail closed; a `substitution` with anything but `allowedBoolean`; a reference (`subject`, `encounter`, `requester`, `performer`, `recorder`, `reasonReference`, `supportingInformation`, `basedOn`, `insurance`, `eventHistory`) that carries a `display`, an `identifier`, a `type`, or a reference string that is not `<ResourceType>/<id>` or `urn:uuid:<id>`; a dosage `site` or `method`; an as-needed dosage whose `timing.repeat` the reader cannot represent (a `periodUnit` of s, min, or a, or a repeat without a usable `frequency`, `period`, and `periodUnit`), because the printed line would otherwise lose the interval and say only "as needed"; a route coding that is not a known SNOMED CT route code or that carries a `version`; or a route text or display that is not the standard name of the coded route. The reader ignores no field: every key in the allowlist is either read or constrained as above.

The medication. An order's medicine comes from `medicationCodeableConcept`, or from a `medicationReference` of the form `Medication/<id>` or `urn:uuid:<id>` that resolves to exactly one `Medication` resource in the same bundle (matched by `id`, by entry `fullUrl`, by the id named in a `urn:uuid:` reference, or by an absolute `fullUrl` ending in the reference; two matches, or a `Medication` that no order references, refuse the request) that carries only `resourceType`, `id`, `meta`, `code`, and a `status` of active; that resource's `code` is then read as the concept. An order with both fields, with a reference that matches no `Medication`, or with a reference carrying a `display` yields no name and no usable dose, timing, or route. The concept may carry only `text` and `coding`; each coding may carry only `system`, `code`, `display`, and `userSelected`, with a system of RxNorm, NDC, or SNOMED CT and a code of that system's shape when either is present. The printed name is the `text`; a coding `display` may be the text name alone, or the text name followed only by a strength and dose form drawn from a fixed grammar: numbers, the dose units of the unit table (with RxNorm's UNT) optionally over mL, L, g, mg, HR, or ACTUAT, a fixed list of dose-form words such as Oral Tablet, Extended Release, Injectable Solution, and Prefilled Syringe, and a final bracketed brand name that is in the lexicon (so `Lisinopril 10 MG Oral Tablet` and `Insulin Lispro 100 UNT/ML Injectable Solution [Humalog]` pass, and `Oxycodone 5 MG Oral Tablet as needed for pain`, `Methotrexate 15 MG Weekly Oral Tablet`, and `Metoprolol Tartrate 25 MG Oral Tablet` under the text `Metoprolol` do not). Without a `text`, the displays must all be the same bare name. Any other display makes the order yield no name and no usable dose, timing, or route. Finally the name is printed only if, lowercased, it equals a line of `data/rxnorm_names.txt`, the RxNorm ingredient, precise ingredient, multiple ingredient, and brand names; a name outside the lexicon (for example `Warfarin Held`, `insulin aspart`, which RxNorm lists as `insulin aspart, human`, or `Toprol-XL`) has no usable name, so a slot that needs it is blocked. The proved structural rule (letters, spaces, and hyphens, at most 60 characters and 5 words, no forbidden or stop word) still applies on top of the lexicon.

Options:

- By default the layer blocks any output that does not give an instruction for every active order. `--allow-omissions` and `--number-only` turn this off, and they are the only options that let an active order go unnamed without a block. They also turn off the noActiveOrder check, so an empty or fully inactive chart can release a framing sentence.
- `--extra-words FILE` adds lowercase words, one per line, to the vocabulary for framing sentences. The default vocabulary has 67 words (`vocab_length` in `DoseGate/Proofs/Vocab.lean` pins the count); it includes `doctor`, `nurse`, `pharmacist`, and `care team`, so a framing sentence can attribute the orders to a doctor, nurse, or pharmacist even when the record's requester says otherwise, a provenance claim the layer does not check. Forbidden words stay forbidden. The guarantees about framing sentences hold for the default vocabulary only: added words can be medical (for example "treats" or "diabetes"), and the layer does not check them, so the deployment must keep them free of medication names, indications, and quantities.
- `--ignore-free-text` reads the dose, timing, and route of an order even when the order has a `note` or its dosage has `text`, `additionalInstruction`, or `patientInstruction`. By default such an order has no usable dose, timing, or route, because free text can hold or limit the structured dose. Use this option only when the free text is generated from the structured fields. In the raw synthetic bundles, 193 orders say "Every twelve hours as required" in their free text with asNeededBoolean false. Those orders still block under this option, because their dose, route, or unit is unusable. An order of this kind with usable structured fields prints as a scheduled dose, so this option must not be used on records of this kind without checking each order.
- `--number-only`, for `render` and `serve`, lets the model hold a conversation while keeping every number from the chart. A sentence with a dose, route, frequency, sig, or total must be one of nine fixed shapes, such as `Your dose of {{drug:m1}} is {{dose:m1}}.` or `Take {{drug:m1}} {{frequency:m1}}.` Any other sentence may hold no slot and may use only words from `data/prose_words.txt` or `--extra-words`, and never a number-like word. `number_only_guarantee` proves that the number-like words of released text are exactly those of the filled value slots. It does not check meaning: `Stop taking it.` and a wrong reason for a medicine still print, an active order may go unnamed, and the proof depends on a person reviewing the word list.

The input reader gives a dose written as a count (tablet, capsule, puff, or drop) no usable dose, so an output that prints that dose is blocked with `missingField`, because a count gives the patient no strength to check; send strengths instead. Under the default settings, the layer blocks with the reason `noActiveOrder` when no order is active, so an empty or fully inactive order list never produces text.

When the layer blocks, the application must show something else and must never show the block detail to a patient, because it can quote model text. `dosegate fallback` reads a request like `render`, ignores its output, and renders one instruction per active order through the same proved code.

## Reproducing the evaluation

All commands run from the repository root with Python 3 (standard library) after building. Model generation needs MLX LM 0.32.2 for Qwen3.5-4B and Ollama for the other two models.

- `eval/build_cases.py` rebuilds `eval/data/cases.jsonl` from the Synthea bundles (not distributed).
- `python3 eval/free_text_share.py` counts the active MedicationRequests and their free-text fields in the raw Synthea bundles, read in place from `SYNTHEA_FHIR_DIR`, and writes `eval/data/free_text_share.json`.
- `eval/generate.py` generates model outputs. Version 2 runs used `HALF=test` with `MODEL`, `BACKEND`, `OUT`, and `CONDITIONS` set as in the paper, and the four Claude runs used `BACKEND=anthropic` with `MAX_TOKENS=2000`, which sends no temperature, so the `temp` field in those four files (0.0) is a placeholder and does not record a greedy decoding setting; outputs are `eval/data/generations_v2_*.jsonl`.
- `TAG=v2_qwen3.5-4b python3 eval/score.py` (and likewise for `v2_medgemma-4b` and `v2_llama3.2-3b`) re-gates every stored output with the built binary and writes `results_all_<tag>.json` and `final_gate_decisions_<tag>.json`.
- `TAG=<tag> python3 eval/controls.py` runs the comparison filter, the planted-error test, and the attack counts (`controls_<tag>.json`).
- `python3 eval/models.py` writes a seven-model summary (`models_summary.json`), covering the three open models and the four Claude runs (Table 3 shows only the open models); `python3 eval/describe.py v2_qwen3.5-4b v2_medgemma-4b v2_llama3.2-3b v2_claude-haiku-5-5 v2_claude-sonnet-5-5 v2_claude-opus-5-5 v2_claude-fable-5-1` writes case counts and reading grades (`describe.json`); `python3 eval/latency.py v2_qwen3.5-4b` times the binary.
- `python3 eval/attacks.py IN OUT` runs an adversarial corpus through both filters. Corpora: `eval/data/attacks.jsonl` (development), `eval/data/heldout/` (round h1, against version 1), `eval/data/heldout2/` (round h2, against version 2), `eval/data/heldout3/` (round h3, against version 2.1), `eval/data/heldout4/` (round h4, against version 2.2), `eval/data/replay_v21/` (the first three corpora replayed through version 2.1), `eval/data/replay_v22/` (the first four corpora replayed through version 2.2), and `eval/data/replay_v23/` (all five corpora replayed through version 2.3; in each replay folder a results file is the output of `python3 eval/attacks.py` on the `.jsonl` file beside it, and `labels.json` carries the adopted labels to the texts that version still releases; `python3 eval/replay_v22.py` and `python3 eval/replay_v23.py` rebuild those files and print the replay rows). `python3 eval/labels.py` summarizes the labels. The protocol is in `eval/labeling_protocol.md`.
- `bash eval/pinned_rerun.sh SCRATCH_DIR` rebuilds the layer at the two held-out commits (59c5f32 and ef2cc98), reruns both held-out rounds through both filters with the current `eval/attacks.py`, compares every record with the stored results, and writes `eval/data/pinned_reruns.json`. Run it from the repository root.
- `eval/data/v2_review/` holds the blinded labels of model outputs.
- `python3 eval/bootstrap.py v2_qwen3.5-4b v2_medgemma-4b v2_llama3.2-3b v2_claude-haiku-5-5 v2_claude-sonnet-5-5 v2_claude-opus-5-5 v2_claude-fable-5-1` writes the patient-cluster intervals to `eval/data/bootstrap.json`.
- `python3 eval/maxima.py` writes the label-limit counts to `eval/data/maxima.json`.
- `python3 eval/fallback_rate.py` writes the fallback counts to `eval/data/fallback_rate.json`. It runs the binary at `.lake/build/bin/dosegate` unless the environment variable `DOSEGATE` names another binary.
- `python3 eval/label_rule_sweep.py` scans the labeled outputs for the two patterns of the labeling rule and writes `eval/data/label_rule_sweep.json`.
- `python3 eval/label_change_counts.py` recomputes the misstatement counts with and without each label change (Table 2A) from the label files.
- `python3 eval/vocab_rxnorm_check.py` looks up the vocabulary and name stop words in RxNorm (needs network access) and writes `eval/data/vocab_rxnorm_check.json`.
- `python3 eval/omissions.py` prints the omitted-order counts in Table 2 (6 of 23, 11 of 36, 19 of 54, and 33 of 80 faithful outputs).
- `eval/coded_timing_check.py` needs the raw Synthea bundles, read from the folder named by `SYNTHEA_FHIR_DIR`, and writes `eval/data/coded_timing_check.json`.

Files without a `v2` tag (`generations.jsonl`, `results_all.json`, and so on) are the version 1 study; files in `eval/data/pilot/` are from an earlier pilot and are not reported.
